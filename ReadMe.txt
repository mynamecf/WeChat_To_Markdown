【微信公众号文章转 Markdown 浏览器插件】

一、这个插件做什么

   在微信公众号文章页点一下，把正文存成本地 Markdown 文件，图片一并下载到
   本地文件夹。Obsidian、Typora、VS Code 打开就能读，不需要再手动复制粘贴。

二、工作流程

   Content Script   注入文章页，等图片懒加载完成，提取标题、正文与图片地址。
   Background       下载图片、转 Markdown、把图片路径替换成本地相对路径，
                    再通过 chrome.downloads 保存 md 与图片。
   Popup / 浮窗     发起导出、显示进度。浮窗固定在页面右下角，位置可拖动。

三、项目结构

   manifest.json            扩展配置（权限、入口、注入清单）
   background.js            后台调度：导出锁、图片并发下载、路径与统计
   content.js               正文提取与 Markdown 转换（Turndown 规则）
   floating.js              页内浮窗（closed shadow DOM，页面脚本读不到）
   popup.html / popup.js    工具栏弹窗
   options.html / options.js 详细配置页
   version.json             版本公告（供「新版本提醒」读取，不参与打包）

   lib/
     defaults.js            全局默认配置（唯一数据源）
     naming.js              命名模板解析、路径净化、图片引用路径
     injectlist.js          注入清单与结果解析（单一来源）
     download.js            下载原语（等待终态、并发控制、data URL）
     codeblock.js           代码块整理
     compat.js              微信特殊排版兼容（伪标题、浮动序号、手写序号）
     blocks.js              引用块与嵌套列表归一
     tables.js              表格单元格摊平与 GFM 表格规则
     attachment.js          视频 / 语音附件（输出在线链接）
     imagepost.js           图片消息（图文 / 小绿书）适配
     update.js              版本检查（比版本号、节流）
     turndown.js            第三方库（本地内置，勿改）
     turndown-plugin-gfm.js 第三方库（本地内置，勿改）

   test/                    单元测试（node --test + jsdom）
   tools/                   打包脚本（build.js 出商店 zip，pack.js 出 crx）
   docs/                    开发日志（DEVLOG.md，含每次改动的实现细节）

四、安装（Chromium 系）

   商店版：Chrome Web Store / Edge Add-ons / Opera Add-ons 搜索插件名安装。
   离线版：npm run build 产出 dist/chromium/ 与 dist/wxmd-<版本>-chromium.zip，
           解压后在 chrome://extensions 开启开发者模式，
           点「加载已解压的扩展程序」选 dist/chromium。
   注意：请加载 dist/chromium，不要加载项目根目录——根目录里有测试、脚本
         和构建配置，浏览器会一并读入并报错。

AU.图片命名支持 {{ext}} 变量（v16.30.0）：
1.图片文件名模板新增 {{ext}}，值是这张图的真实格式（png / jpg / webp / gif / bmp / svg），
  不含点。例如 {{index1}}.{{ext}} 得到 1.webp，IMG_{{ext}}_{{index1}} 得到 IMG_png_1。
2.格式推断与落盘补后缀共用同一份规则（tp > 路径 webp > wx_fmt > 路径前缀 > 文件后缀），
  不会出现「模板里写 webp、实际存成 png」。
3.模板自己写了后缀时不再重复补：{{index1}}.{{ext}} 落盘就是 1.png，不是 1.png.png。
4.该变量只在「图片文件命名」里有值，文件夹名与 Markdown 名称模板里写它渲染成空串。
5.配置页可用变量增至 14 个，预览与真实落盘一致。

AV.{{ext}} 改为大写并放开适用范围（v16.31.0）：
1.变量值统一大写：{{ext}} 现在输出 PNG / JPG / WEBP / GIF / BMP / SVG，
  不再是小写。IMG-{{ext}}-{{index1}} 得到 IMG-PNG-1，{{index1}}.{{ext}} 得到 1.PNG。
2.不再是图片专用：文件夹名、Markdown 名称模板里同样有值，取 MD（大写）。
  例如 Markdown 名称写 {{title}}.{{ext}}，导出就是 文章.MD。（此项已在 v16.32.0 收回，见 AW）
3.Markdown 名称自己带后缀时不再重复拼 .md：{{title}}.{{ext}} 得 文章.MD，
  不是 文章.MD.md。判断规则与图片补后缀共用同一个 withRealExt。
4.配置页预览同步：先补后缀再去重，五种模板写法预览与落盘一致。
5.不写 {{ext}} 时，自动补的后缀仍是小写（IMG_1.png），与升级前逐字一致，
  老用户的导出结果不受影响。

1.{{ext}} 只在「图片文件命名」里有值。文件夹名、Markdown 名称等模板里写它
  渲染成空串（不留字面量），不再取 MD。上一版把范围放大到所有模板，这一版收回。
2.大写保留：仍然输出 PNG / JPG / WEBP / GIF / BMP / SVG，不含点。
  例：IMG-{{ext}}-{{index1}} 得 IMG-PNG-1，{{index1}}.{{ext}} 得 1.PNG。
3.Markdown 名称自己手写了 .md 时不会重复补：模板 {{title}}.md 得到 文章.md，
  不是 文章.md.md。这条与 {{ext}} 无关，属于命名清洗。

AX.{{ext}} 也可用于图片保存目录（v16.33.0）：
1.适用范围：{{ext}} 现在可用于「图片文件命名」和「图片保存目录」两处。
  逐篇归档用 imageFolder，平铺归档用 sharedImageFolder，两处都生效。
2.图片命名按每张图各取各的真实格式；图片目录一篇只解析一次，
  取正文第一张可下载图片的格式。例如目录模板 {{ext}}/img，正文首图是 png，
  就落到 PNG/img/ 下。
3.一篇里混着 png / jpg 时目录名不会按格式拆开——目录名只有一个，这是必然取舍。
4.没有可下载图片（纯文字文章、或全被白名单拦掉）时变量为空，目录名少这一段，
  不会留下 {{ext}} 字面量。
5.其余模板（逐篇文件夹名、Markdown 名称）里仍然是空串，与上一版一致。

AY.图片保存目录按格式分目录（v16.34.0）：
1.目录模板里的 {{ext}} 改为按每张图各取各的格式，不再只取正文第一张。
   {{ext}}/img 会得到 PNG/img/ 与 JPG/img/ 两个子目录，互不覆盖。
   （上一版 v16.33.0 的「一篇只解析一次、取首图格式」已作废。）
2.图片命名与图片目录用同一张图的格式，不会出现 JPG/img/ 里躺着 .png 文件。
3.Markdown 里每张图的引用分别指向自己那个目录（./PNG/img/… 与 ./JPG/img/…），
   与实际落盘路径一致；目录太长时两者仍按同一份压缩结果收短。
4.目录里的 index 类变量（{{index}} / {{index1}}）仍固定取第一张的序号，
   不会一张图一个目录。
5.模板不含 {{ext}} 时所有图片仍在同一目录，升级前后落盘路径逐字不变。
6.纯文字文章（没有可下载图片）时变量为空，目录名少这一段，不留 {{ext}} 字面量。
7.配置页预览同步：三张示例图分别用 png / jpg / png，写 {{ext}} 时能直接看出
   目录被拆成两个；图片后缀也跟着各自的示例格式走。

AZ.配置页顶部信息卡整理（v16.35.0）：
1.「版本与更新」从页面底部移到顶部，紧跟「导出位置说明」，两张卡同一套样式，
  同样可折叠、默认收起。
2.删掉「导出位置说明」里「扩展无法指定绝对路径……加权限也绕不过」那一段：
  上一段已经说明目录只能在浏览器里改，这段属于重复。
3.卡片收起时状态看标题行角标：未开启检查 / 每 24 小时检查 / 正在检查 /
  检查失败 / 已是最新 / 已忽略 v… / 发现新版 v…（实心高亮）。
  有新版时不必展开也能一眼看到。
4.折叠交互与「可用变量」共用同一段代码，三处行为一致。

六、已知限制

1.视频号内容拿不到视频文件本体，只能给出指回原文的链接（分片加密 + 需要登录态）。
2.带合并单元格（colspan / rowspan）的表格会少列，文字不丢。
3.「3.14 圆周率」这类加粗短句可能被误判成三级标题。
4.手写序号按作者写的原样保留，不按位置重排。
5.配置页预览用 png / jpg / png 三张示例图猜格式，真实格式要到下载时才确定；模板里写了 {{ext}} 时按每张图的真实格式落盘。
6.导出目录固定为浏览器下载目录，扩展无权指定绝对路径。
