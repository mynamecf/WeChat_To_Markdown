# 微信文章转 Markdown

一个 Chrome / Edge 扩展（Manifest V3），把微信公众号文章一键保存成 Markdown：正文转成干净排版、图片下载到本地、链接落成笔记软件能直接读的相对路径。

当前版本：**1.16.33.0**　｜　更新记录见 [ReadMe.txt](./ReadMe.txt)，逐次改动的实现细节见 [docs/DEVLOG.md](./docs/DEVLOG.md)

---

## 功能

- **一键导出**：点扩展图标 → 导出当前文章，也可以固定在页面上的浮窗里导出。
- **按链接批量导出**：配置页底部「链接导出」进入独立页面，粘贴一串公众号链接（一行一条），点一次「开始导出」就按顺序逐条跑，关掉页面也会继续跑。
- **段落识别**：`section` / `p` / `div` 三种容器都能正确分段——用 `div` 直装正文的模板不会再整篇粘成一段。
- **图片本地化**：图片按序号并发下载（默认 4 并发），Markdown 里替换成你选的引用路径；在线模式则只生成单个 `.md`，图片保留微信图床地址。
- **两种归档方式**：逐篇归档（每篇文章一个文件夹，图片随文归档）／平铺归档（所有文章与附件放在同一层，图片混排）。
- **可配置命名**：文章名、文件夹名、图片目录、图片文件名都支持模板，共 14 个变量（`{{title}}`、`{{author}}`、`{{date:YYYYMMDD}}`、`{{index1}}`、`{{ext}}`…）。
- **特殊排版适配**：代码块围栏化、伪标题还原、浮动序号合并、嵌套列表缩进、样式画的引用块、GFM 表格、图片消息（图文／小绿书）补图并清 UI 噪音。
- **标题按模板取**：普通图文读 `#activity-name`，图片消息 / 新版分享页读 `h1.rich_media_title`（这类页面没有 `#activity-name`），再退到 `og:title` 与 `<title>`——换模板也不会导出空标题。
- **视频 / 语音只留链接**：不下载视频本体，正文原位置写在线播放地址。视频号卡片（`mp-common-videosnap`）没有网页播放页，改为指回原文并带 `?wxmd_video=N`，装了扩展时点开会自动滚到那个视频。
- **不联网、不上传**：所有解析与转换都在本机完成，扩展没有账号体系，也不向任何服务器发送内容。唯一可能出网的是「新版本提醒」——**默认关闭**，只有你手动打开后才会去读一个几十字节的 `version.json`。

## 安装

1. 下载或克隆本仓库。
2. 打开 `chrome://extensions`（Edge 为 `edge://extensions`），打开右上角「开发者模式」。
3. 点「加载已解压的扩展程序」，选择本仓库根目录（含 `manifest.json` 的那一层）。
4. 打开任意一篇公众号文章（`https://mp.weixin.qq.com/s/...`），点工具栏里的扩展图标即可使用。

要求 Chrome / Edge **102+**（Manifest V3 + `minimum_chrome_version`）。

修改代码后需要在 `chrome://extensions` 点一次「重新加载」，弹窗和配置页才会用上新代码。

## 支持的浏览器

| 浏览器 | 状态 | 说明 |
|---|---|---|
| Chrome / Edge / Brave / Vivaldi / Opera | ✅ 完整支持 | 102+，同一份安装包 |
| 360 极速 / QQ / 搜狗等 Chromium 内核 | ✅ 可用 | 内核版本需 ≥ 102；用「加载已解压的扩展程序」安装 |
| Firefox | ⛔ 暂不支持 | 后台是事件页而非 Service Worker，`importScripts` 会直接报错，需要单独适配 |
| Safari（macOS / iOS） | ⛔ 暂不支持 | Safari 没有 `downloads` API，图片落盘与同名改名那套逻辑要重做 |
| 手机浏览器 | ⛔ 不可用 | 扩展无法控制下载目录结构；微信内置浏览器更不支持扩展 |

Chromium 全系用同一个包，`npm run build` 产出两份东西：

- `dist/chromium/`：解压后「加载已解压的扩展程序」直接装
- `dist/wxmd-<版本号>-chromium.zip`：Chrome Web Store / Edge Add-ons / Opera Add-ons 通用上传包

## 版本与更新

扩展**不会自我更新**（浏览器不允许扩展自我安装），升级只由商店完成，或者你自己换包。内置的只是一个提醒：

- 详细配置 → 「版本与更新」 → 打开「有新版本时提醒我」，**默认关闭**。
- 打开后每 24 小时读一次 `version.json`（地址在 `lib/update.js` 的 `WXMD_UPDATE_URL`，需 HTTPS 且响应头带 `Access-Control-Allow-Origin: *`），只取版本号、更新说明、下载地址。
- 有新版本：工具栏图标显示 **NEW**，配置页显示更新说明，弹窗顶部出现提醒条；也能「忽略此版本」，下个版本仍会提示。
- 关掉开关立刻停止：定时器被清掉，不再发任何请求。

更新方式取决于你是怎么装的：

| 安装方式 | 怎么更新 |
|---|---|
| Chrome / Edge 商店 | 浏览器自动更新，通常什么都不用做；想立刻更新去 `chrome://extensions` 打开开发者模式 → 「更新」 |
| 离线包（解压目录） | 下载新包解压覆盖，再到 `chrome://extensions` 点「重新加载」 |
| crx 双击安装 | 下载新 crx 拖进 `chrome://extensions`，确认替换 |

> 更新不会丢配置：命名模板、开关都保存在浏览器本地存储里。

## 使用

### 弹窗

点扩展图标打开弹窗，可以：

- 选择**图片模式**：「保留在线链接」（只出 `.md`）或「下载到本地」（出 `.md` + 图片文件夹）。
- 选择**归档方式**：「逐篇归档」或「平铺归档」。
- 点**导出当前文章**开始转换，状态提示成功后自动淡出。
- 点「固定悬浮窗」把操作面板钉在页面上，方便连续导出多篇。
- 点「详细配置」进入完整设置页。

### 页面浮窗

固定后文章页右下角会出现浮窗；收起成圆球时，按住可以拖动位置，点击展开／收起。

浮窗展开状态下按 <kbd>Ctrl</kbd> + <kbd>S</kbd>（macOS 为 <kbd>⌘</kbd> + <kbd>S</kbd>）等同于点「导出当前文章」。快捷键只在浮窗展开时生效，收起后按下会触发浏览器自带的保存网页。

### 详细配置

配置页顶栏、弹窗底部、浮窗底部都有「官网 / 问题反馈」入口，地址统一维护在 `lib/defaults.js` 的 `WXMD_LINKS`，留空则自动隐藏。

页面用的是「分组卡」：一张卡里若干行，行间一条发丝线，点哪一行内容就在该行**正下方就地展开**，宽度天然等于整行，和别的配置卡左右边界一致（不会出现「两个标题栏配一个横跨整行的大面板」的错位）。展开的那一行整行铺浅绿、标题与内容连成一块，右侧箭头转 180° 并变绿。各处独立展开，互不收起。

页面上共两处：

- 最上面一张卡，只有一行「导出位置说明」，管下载目录的解释。
- 最下面（「可用变量」之后）一张卡两行：「版本与更新」可折叠，「链接导出」带 `›` 跳到独立页面（新标签打开）。

窄屏（≤900px）结构不变，只收紧缩进与行内留白。

### 按链接批量导出

配置页最下面（「可用变量」之后）的「链接导出」那一行会打开独立页面（`queue.html`），在那里一次贴多条链接，**一行一条**（也可以直接粘整段分享文案，会自动从中挑出链接）。该行右侧的角标会显示队列进度（未开始 / 待导出 N 条 / 导出中 x/y / N 条失败 / 已完成 N 条）：

- 只接受 `https://mp.weixin.qq.com/s/...` 形式的文章页；首页、视频播放页、合集页会被拒绝并说明原因。
- 同一个链接只允许进队列一次（`#rd` 这类锚点算同一篇）。条数不设上限：贴 300、500 条都能进，一次粘贴超过 5000 条会被拒绝（防误贴的硬顶）。
- **超过 200 条会提示风控**：点「开始导出」前弹一次确认，页面也会常驻一条提醒——短时间内大量打开公众号文章，微信可能限流（页面变慢、出验证页、图片 403）。跑完一批再点一次比一口气跑到底稳。
- 点一次「开始导出」就开跑：输入框里有内容会**先入库再启动**，没有就直接续跑未完成的条目，不需要先「加入队列」再点开始；输入框里按 `Ctrl + Enter` 等效。
- 队列**串行**执行，每条会在后台标签页里打开、导完立即关闭，同时最多只有一个标签页。
- 导出用的模式是配置页当前选中的「保留在线链接 / 下载到本地」，不需要在队列里再选一次。
- 关掉这个页面不影响队列，重新打开能看到实时进度；浏览器重启后未完成的任务会继续。
- 页面是独立标签页：点左上「返回配置」会**切回打开它的那个配置页**并把这个标签关掉（找不到原标签才在原地打开配置页），不会留下两个配置页；入口已经开着队列页时再点，直接切过去，不会越开越多。列表往下滚过一屏后，右下角会浮出同样的「返回配置」按钮，省得把页面滚回顶部。
- 失败会写明原因，`页面加载超时` 这类会自动重试 1 次，`未找到文章正文` 这类不重试（重试也是同样结果）。

## 导出结果

逐篇归档、下载到本地时，下载目录下的结构大致如下（取决于你的命名模板）：

```
下载/
└── 20261116_文章标题/
    ├── 20261116_文章标题.md
    └── 2026/11/16/
        ├── IMG_20261116153012456_1.png
        ├── IMG_20261116153012456_2.png
        └── …
```

生成的 Markdown 开头带一段 YAML：

```yaml
---
title: '文章标题'
author: '公众号名称'
source: 'https://mp.weixin.qq.com/s/...'
published: '2026年11月16日 10:00'
exported: '2026-11-16T02:30:12.456Z'
---
```

## 配置说明

### 图片引用路径

只改 Markdown 里图片链接的写法，不影响图片实际落盘位置。三种模式：

| 模式 | 输出示例 | 适用场景 |
| --- | --- | --- |
| 相对库内模糊路径 | `2026/11/16/a.png` | Obsidian「最短路径」习惯，由笔记软件自行解析 |
| 相对当前笔记 | `./2026/11/16/a.png` | 以 `.md` 所在文件夹为基准，搬动整个文件夹也不会断链 |
| 自定义前缀 | `/微信/{{noteFolder}}/2026/11/16/a.png` | 自己写前缀，`../` 表示上一级，`/微信/…` 表示库内绝对路径 |

- 自定义前缀里的 `{{noteFolder}}` 会替换成 `.md` 所在文件夹。
- 前缀中的空格会自动编码成 `%20`，否则 Markdown 会把空格后面的内容当成图片 title。
- 逐篇与平铺各存一份引用配置，互不影响。
- Typora 会把开头的 `/` 当成盘符根，库内绝对路径在 Typora 里天然不可用，用 Typora 建议选「相对当前笔记」。

### 命名模板

文章文件夹、Markdown 文件名、图片目录、图片文件名都支持模板；平铺归档另有一套独立模板。可用变量：

`{{title}}` `{{author}}` `{{published}}` `{{published:格式}}` `{{url}}` `{{domain}}` `{{site}}` `{{date}}` `{{date:格式}}` `{{time}}` `{{time:格式}}` `{{index}}` `{{index1}}` `{{hash8}}` `{{ext}}`

`{{published}}` 不加格式时是**页面原文**（微信给的字符串，如 `2026年11月16日 10:00`）；加上 `:格式` 才会解析成日期再格式化，格式标记与 `{{date:格式}}` 完全一致：

| 模板 | 结果 |
|---|---|
| `{{published}}` | `2026年11月16日 10:00` |
| `{{published:YYYYMMDD}}` | `20261116` |
| `{{published:YYMMDD}}` | `261116` |
| `{{published:YYYY-MM-DD}}` | `2026-11-16` |
| `{{published:YY}}` / `{{published:MM}}` / `{{published:DD}}` | `26` / `11` / `16` |

页面给的原文形态不止一种（`2026年11月16日 10:00`、`2026-11-16`、`2026/11/16`、`2026.11.16`、`20261116`），解析器都认；解析不出来（`昨天`、`3 天前`）时渲染成空串，不会生成错误日期。

微信的发布时间只到分钟，所以 `ss` / `s` / `SSS` 用在 `{{published:格式}}` 上会得到 `00` / `0` / `000`（原文带秒时才取真实值）；要「导出这一刻」的秒或毫秒请用 `{{date:格式}}` / `{{time:格式}}`。

`{{ext}}` 是图片的真实格式，**大写且不含点**（`PNG` / `JPG` / `WEBP` / `GIF` / `BMP` / `SVG`），可用于「图片文件命名」和「图片保存目录」：

- **图片文件命名**：按每张图各取各的格式。
- **图片保存目录**：同样按每张图各取各的格式——一篇里混着 png / jpg 时会分别落到 `PNG/` 与 `JPG/` 两个子目录，Markdown 里每张图的引用分别指向自己那个目录。
- 其余模板（逐篇文件夹名、Markdown 名称）里渲染成空串。

模板可以自己决定后缀位置：

| 模板 | 结果 | 说明 |
|---|---|---|
| `IMG_{{index1}}` | `IMG_1.png` | 不写 `{{ext}}`，按真实格式自动补后缀 |
| `{{index1}}.{{ext}}` | `1.WEBP` | 已带后缀，不会变成 `1.webp.webp` |
| `IMG_{{ext}}_{{index1}}` | `IMG_WEBP_1.png` | 格式写进名字主体，落盘仍补 `.webp` |
| `{{ext}}/img`（图片目录） | `PNG/img/`、`JPG/img/` | 按每张图的格式分目录，一篇可落在两个目录 |

不写 `{{ext}}` 时，自动补的后缀是小写（`IMG_1.png`），与升级前完全一致；想让后缀大写，自己写 `.{{ext}}`。

### 图片下载范围

默认只下载**微信图床**上的图片（`qpic.cn`、`qlogo.cn`、`wx.qq.com`、`gtimg.cn`、`gtimg.com`，含子域名）。文章里指向其他站点的图片不下载，Markdown 里保留原始在线链接。

这不是洁癖：图片地址完全由文章作者控制，而扩展没有 DNS 解析能力，只看域名字面挡不住「域名 A 记录指向内网」的探测请求。白名单是唯一可靠的解法。

确有可信第三方图床时，在配置页「下载到本地配置」底部勾选「下载第三方图床的图片」即可；内网 / 本机地址（`127.0.0.1`、`10/8`、`192.168/16`、`172.16/12`、link-local、IPv6 ULA 等）无论是否勾选都不会下载。

### 导出位置

导出目录固定为浏览器下载目录，扩展无法指定绝对路径（Chrome 没有提供这个能力）。想放进子文件夹，在模板前面加前缀即可，例如 `微信文章/{{date:YYYYMMDD}}_{{title}}`，最终落在 `下载/微信文章/…`。

配置页会显示上一次导出反推出的真实下载目录；如果开了「下载前询问每个文件的保存位置」，则显示「无法确定」，不会猜错。这个路径只存在本机扩展存储里。

## 已适配的排版

公众号排版大量依赖 `section` + 行内样式，以下这些形态做了专门处理：

- **段落容器**：`<section><span>`、`<p>`、`<div>` 都按块级处理，段与段之间留一个空行；列表项里的容器不额外补空行（避免紧凑列表被撑散），表格单元格里的容器压成一行。
- **代码块**：编辑器导出的 `<pre><span 工具栏/><code>…</code></pre>`、等宽 `<p>` 成组、伪 `pre`，统一整理成 ``` 围栏，保留缩进与空行，修复 `publicclass` 这类关键字粘连，工具栏文案（复制代码 / 语言名）按需丢弃或当作围栏语言。
- **伪标题**：靠字号、颜色、下边框伪装的标题（「一、背景」「3.1 开箱即用」）还原成 `##` / `###`。
- **浮动序号**：`float:left` 画的「1.」序号并回正文同一行，不再单独成段。
- **手写序号去重**：`<ol>` 里作者手打的「1. 2. 3.」不再和自动编号叠成「1.  1\.」。
- **嵌套列表**：排版器把子列表挂在父 `ul` 下（而不是 `li` 里）时，挂回正确的父项并保留缩进层级。
- **引用块**：用左右边框画出来的引用恢复成 `>`；真标题即使带左边框也不会被误拆成引用。
- **表格**：`<table>` 单元格里常见 `<section><span>` 包裹，会被摊平成一组标准 GFM 表格行；单元格内多段用 `<br>` 换行，文字里的 `|` 自动转义，图片格子只占一行。
- **图片消息（图文 / 小绿书）**：真图在正文容器之外的轮播区，按 DOM 顺序补到描述文字之后，取 `data-src` 原图，并清掉「原文」「地区,时间,」等页面 UI 噪音。轮播是虚拟渲染（后台标签往往只挂 1 项），所以优先用页面主世界的 `cgiDataNew.picture_page_info_list` 全量清单：background 先把它写进 `<html data-wxmd-pics>`，content.js 再读，DOM 采集只作兜底。
- **视频号卡片**：正文里嵌别人发的视频号视频（`mp-common-videosnap`）识别为 `[视频（视频号 · 新华社）](原文?wxmd_video=1)`；这类卡片渲染在 shadow DOM 里，只有播放按钮和昵称，没有 `<video>`，也没有网页播放页。
- **播放器 UI**：视频播放器整台外壳（点赞面板、倍速条、「已关注 / 观看更多 / 视频详情」）整块替换成一条链接，不再把 UI 文案混进正文。

## 已知限制

- **视频 / 语音不下载本体**：视频直链带会过期的 `auth_key`，视频号内容拿不到可分享文件，下载下来往往是坏文件；因此在正文里保留在线链接。
- **视频号只能点回原文**：`data-url` 实测返回的是封面 JPEG（540×720），页面里没有 `channels.weixin.qq.com` / `weixin://` 这类地址，真实播放流要带微信登录态调 `mp/appmsg_video_snap` 且分片加密，扩展拿不到。
- **`?wxmd_video=N` 的定位依赖扩展**：微信页面在加载后约 300ms 内会 `replaceState` 抹掉 URL 里的 hash，浏览器自带的 `#:~:text=` 因此必然失效（实测 4s 后 `scrollY` 仍是 0），只能由扩展在页面就绪后自己滚。没装扩展、或在手机微信里打开时，参数无害但不会跳转。
- **超过 1.4 MB 的 Markdown**：导出受 Chromium 约 2 MB 的 data URL 长度限制。超限在下载图片之前就会拦下并给出建议：在线模式建议改「下载到本地」（相对路径比完整 URL 短得多），本地模式建议缩短目录 / 命名模板。
- **第三方图床的图片默认不下载**：见上方「图片下载范围」，需要时在配置页打开开关。
- **代码块里本身含一行 ``` **：收尾整理靠 ``` 识别围栏边界，代码内容里出现独立的三反引号行会被当成分隔符（极罕见，未做转义）。
- **「3.14 圆周率」这类文字**：一位整数 + 两位小数、且被加粗的独立段落，可能被当成三级标题（正则分不清 `3.1` 与 `3.14`）。真实文章里通常不加粗，触发概率很低。
- **手写序号不纠正**：作者写错（例如第 8 步写成「1.」）就按原文保留，不做跨列表顺延推断，避免误伤两组独立的编号列表。
- **图片下载失败**：该图在 Markdown 里回退成原始在线链接，不会写成不存在的本地路径，至少点得开。
- **合并单元格**：`colspan` / `rowspan` 没有对应的 GFM 语法，带合并的表格会少列（文字不丢）；没有表头的表格按原 HTML 保留。
- **配置页预览的扩展名**：预览路径固定按 `.png` 示例展示，实际落盘按图片真实格式（jpg / png / gif / webp / svg）命名。
- **批量导出会连续开标签页**：每条链接都会短暂打开一个后台标签页（不在前台抢焦点），导完自动关闭。一次跑几十条时标签栏会闪动，这是无头式导出的代价——复用页面里的真实 DOM，才能保证和手动导出结果完全一致。
- **短时间内导太多篇可能触发微信风控**：连续打开十几篇公众号文章，页面可能返回验证页或「环境异常」，表现为队列里连续多条 `未找到文章正文`。遇到时暂停一会儿再继续，已成功的条目不受影响。
- **批量导出不抢焦点，但不能最小化**：标签页是非激活状态，正常不影响你切到别的窗口；若浏览器设置里开了「打开新标签时切换过去」，队列每次都会把焦点抢走一下，建议关掉该设置。

## 安全说明

- 只申请 `activeTab`、`scripting`、`downloads`、`storage`、`tabs`、`alarms`，host 权限仅限 `https://mp.weixin.qq.com/*`。`alarms` 只用于「新版本提醒」的 24 小时定时检查，开关默认关闭。
- 文章里的图片地址由作者控制，扩展会拒绝下载指向本机 / 内网（`127.0.0.1`、`10/8`、`192.168/16`、`172.16/12`、link-local、IPv6 ULA 等）的图片；默认还要求命中微信图床白名单，因为字面 hostname 判断挡不住「域名解析到内网」。被拦下的图片只保留在线链接。
- 浮窗使用 closed Shadow DOM，页面脚本无法读取或模拟点击浮窗按钮。
- 正文提取、转换、落盘全部在本机完成；除图片本身来自微信图床外，不向任何第三方发送数据。唯一的例外是配置页里手动开启的「新版本提醒」：开启后会定时拉取 `version.json`（只带版本号查询，不包含任何文章内容），关闭即不再发请求。

## 开发

- 纯原生 JS + HTML/CSS，无编译步骤，改完直接在 `chrome://extensions` 重新加载；发布时才需要打包。
- 回归测试（首次需 `npm install`，只装 jsdom）：

  ```bash
  npm test       # 91 个用例：段落、表格、代码块、引用/列表、图床白名单、图片消息（含图集桥）、命名、按格式分目录、链接队列、版本比较
  npm run check  # node --check 六个入口脚本
  ```

  夹具在 `test/`，用 jsdom 注入**真实的** `lib/` 与 `content.js`，不复制业务逻辑——所以测过的就是线上跑的同一份代码。

- 打商店包 / crx（可选）：

  ```bash
  npm run build  # 产物：dist/chromium/（解压即装）+ dist/wxmd-<版本>-chromium.zip（三家商店通用）
  npm run pack   # 产物：WeChat_To_Markdown.crx / .pem，约 0.2 MB
  ```

  直接 `chrome --pack-extension=.` 会把 `node_modules`、`test`、`.git` 一起打进去（3 MB+），两个脚本都只复制运行必需文件。`.pem` 是签名私钥，别提交、别丢——丢了就没法用同一个扩展 ID 发新版。

- 调试技巧：`content.js` 顶部把 `DEBUG` 改为 `true`，会打印正文根节点命中情况、图片统计、被拦下的图片等日志；单篇文章出问题时先看这一层。
- 关于官网 / 反馈入口：地址只在 `lib/defaults.js` 的 `WXMD_LINKS` 里维护，改完重新加载扩展，弹窗、配置页、浮窗同时生效。
